# Agent 走出会话，专属来自积累而非定制

**“Agent 进入全新阶段”作为方向判断成立，作为成熟度判断偏强**。五份材料共同记录的，是工程重心从“在一个会话里把一件事做好”移到“会话之外那层让 Agent 没人触发也能醒来、记事、少打扰人的架构”，而不是出现了新理论，也不是出现了可以放心托付的稳定系统。这五份材料其实是同一次转向的五个切面：两篇厂商一手设计文档（DeepSeek Harness 团队 10 月 31 日、Anthropic 11 月 13 日）、一个官方研究原型、一个独立的个人开源实现，以及一篇“读完当天照做”的实践记录，两周之内各自落到几乎相同的形态上。行业证据支持这个方向：2026 年 4 月到 10 月，Anthropic、Google、Meta、OpenAI 和中国大厂同步推出了“云端常驻、自带电脑、带记忆、可定时和事件触发”的同构产品；但最近一次独立测量里，公开前沿模型 80% 成功率对应的任务时长只有约 1.5 小时，企业 AI 实际支出约为预算的 2.5 倍，常驻 Agent 的安全事故也集中出现在这一年。Agent 的终极方向因此不是一条越拉越长的无人值守链路，而是一张“常驻协作者”网络：通用模型加通用 harness 做底座，每个实例有自己的电脑、记忆、身份和授权边界，人退到设目标、授权和验收的位置，系统上限由“结果能否验证、权限能否放心交出”决定。“每个人都有专属 Agent”大概率成真，“每个人都定制自己的 Agent”不会：专属性主要来自平台为每人实例化的 Agent，加上自动积累的记忆和用户点头授权的连接器，亲手搭建和深度定制的始终是少数建造者，而这五份材料的作者恰好都属于这个少数。需要事先说明的限制是：微信原文是经公开转载读到的，两个仓库只读了源码没有运行，文中多数性能和成本数字是厂商或作者自述，最后一节逐项标注。

## 两篇厂商文档、两个仓库、一篇实践，两周内落到同一形态

五份材料的证据分量差别很大，先把性质摆清楚：两篇是厂商的一手设计文档，两个是可以读源码的仓库，一篇是带自测的二手解读。

| 材料 | 性质与日期 | 它实际说了什么 | 它自己承认的限度 |
|---|---|---|---|
| (1) B 站《Anthropic刚教的24小时agent，我当天做出来了》 | UP 主花叔v 的二手解读加一手实践，2026-11-14 | 讲清 (2)(3) 两篇，并让 Claude 照 (2) 在自己的开源工具 FanBox 2.20.0 里做出本地版“离开时叫我”和微信值守 | “目前不算是一个特别成熟的可以24小时不停运行的agent系统”；每种情况只测了一两次 |
| (2) Anthropic《Building always-on agents》 | 厂商最佳实践，2026-11-13，作者 William Hu | 内核循环不变，要补的是外层五个 primitives：event inbox、timers、memory、permissions、outbox；“always-on”只是用户体验，Agent 大部分时间在睡 | 没有代码和客户案例；用词是 “resurgence”；权限被点名为风险最大处 |
| (3) DeepSeek Harness 团队《Super-agent 设计探索》 | 厂商架构探讨，2026-10-31，执笔 Yujia Qiao | 瓶颈从模型能力转到人的注意力；用 Router/Worker 双层、事件驱动、按信道说话、计算/状态/环境分离、Watchdog 支撑“连续、高效、主动、持久” | “并非对 DeepSeek Harness 现有产品功能的介绍”；“我们并没有提出全新的理论”；实验“仅作为初步参考” |
| (4) deepseek-ai/dsh-superagent-prototype | (3) 的配套研究原型，同日发布，MIT，单个 commit | 只服务一个 GitHub 仓库的团队级主动式 coding agent；把授权链和“少占注意力”做成代码强制的规则 | “not an official DeepSeek product”；Watchdog、长期记忆、沙箱均未实现 |
| (5) KKKKhazix/agent-autoloop | 个人开源项目，约 2026-11-03 公开，MIT | 本机事件驱动的“自动化中台”：确定性内核派活，CLI Agent 一轮即退，等人拍板时零进程、零 Token | 多数集成只在模拟环境验证；没有预算上限；“这挡不住所有提示注入” |

时间上最早的是材料 (3)。它的出发点是一句观察：“据我们观察，一个人通常只能同时跟进 3 到 5 个活跃 Session。在这种设计下，单任务的上限取决于模型能力，多任务的上限取决于人的注意力。”据此它主张“Session 应当是系统的实现细节，而不应是用户的认知负担”，让人只面对一个跨信道连续的常驻实体，背后由只管交互和派单的 Router 与各自隔离上下文的 Worker 并行干活，IM 里单次回复不超过 100 词 ([Offloop 转载的全文](https://offloop.org/zh-CN/learn/exploring-deepseek-super-agent-design))。文章的实验是合成消息流（约 300 条消息、约 20 条工作请求、每种方案跑 5 次），编码环节“用一个只消耗时间的工具代替”，衡量的是调度而不是任务质量。结果里 Super-agent 的完成时间 p50/p95 为 12.4/15.7 分钟；带 Subagent 工具的单 Session 在中性提示下是 20.4/29.5 分钟，换成“优先委派”提示后 p50 降到 13.8 分钟、p95 仍有 29.0 分钟；代价是读缓存 token 2323 万对 605 万，约 3.8 倍 ([Offloop 转载的全文](https://offloop.org/zh-CN/learn/exploring-deepseek-super-agent-design)；基线组完整数字来自第三方对结果表图片的读取：[redreamality](https://redreamality.com/blog/deepseek-super-agent-router-worker-architecture/))。也就是说，**双层架构真正稳定的优势在长尾（p95），不在中位数**。这组实验里最有信息量的发现其实是：中性提示下模型 5 次运行一次都没有主动委派，说明让模型自己决定要不要分工并不可靠，分工得靠系统结构强制。

材料 (4) 是这篇文章“阅读原文”指向的仓库，它比文章小得多。README 第一句就是 “Research prototype for reference only, not an official DeepSeek product”，并说明文章里的部分设计 “are directions for future development and are not implemented in this prototype” ([README](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/README.md#L3))。源码显示它是架在 DeepSeek Harness 之上的编排层：一个常驻的 orchestrator 会话负责研判和派单，每张工单一个 worker 会话，状态落在一个 SQLite 文件里。它做成一等机制的不是自主性，而是授权和注意力：主动接单默认是只记录“would accept”而不执行的 `observe` 模式 ([docs/002](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/002-authorization.md#L93-L101))，Agent 不能给自己排程 ([docs/001](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/001-domain.md#L50))，哲学文档把每条消息、每个设置都按“花掉谁的注意力”来衡量 ([docs/000](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/000-philosophy.md#L7))。文章里的 Watchdog、长期记忆和云端存算分离在仓库里检索不到；执行侧也没有操作系统级沙箱，部署文档直言两个 preset 都以运营者的 OS 用户、`danger-full-access` 权限运行 ([docs/006](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/006-deployment.md#L19))。仓库版本 0.1.0，11 月 14 日抓取页面时约 23.1k star ([GitHub](https://github.com/deepseek-ai/dsh-superagent-prototype))，热度远高于成熟度。

材料 (2) 晚两周出现，立场更克制，结构更干净。它的核心论断是 “Underneath, they run on the same core loop as other agents. The difference is the surrounding architecture”，并把这层架构拆成五个 primitives；它最有穿透力的一句是 “An always-on agent is not actually ‘always on.’ This is just a description of the user experience”——Agent 绝大部分时间在睡眠、不花 token，被事件或定时器叫醒做一次短暂的 run，写回状态再睡 ([Anthropic](https://claude.com/resources/articles/building-always-on-agents))。文章建议 “starting with one inbox per user”，把权限称为 “where always-on agents carry the most risk”，并要求 Agent “start quiet and then earn more of the user's attention over time”。它对“为什么是现在”只给了两条理由：模型更知道什么时候该回来问一句，以及智能在变便宜。唯一的硬数字是 Opus 5.5 在一个长程编码基准上每解决一个任务的成本比 Opus 5 低 78%，而原文紧跟着的限定是典型负载只低 40%；所链接的文档说明该基准是 SWE-bench Pro 的一个子集 ([Anthropic 文档](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence))。

材料 (5) 名字里有 “autoloop”，但它不是让模型围着一个目标自己转到做完的 Ralph 式循环。README 的定位是“极轻量的自动化中台”，标语是“让你的命令行 Agent 在后台自己接活、自己跟进到底；平时不烦你，遇到拿不准的事才发卡片找你拍板” ([README](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/README.md#L3))。确定性内核只负责收事件、按规则派活、记账和到期叫醒；干活的是用户本机已登录的 Claude Code、Codex 等 CLI，每次只跑一轮就退出；要问人就结束这一轮，等待期间不占进程、不花 Token，人回答后再续接原会话 ([README](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/README.md#L66-L72))。名字里的 loop 指的是“事件、规则、Agent、回执、新事件”这个闭环。协议文档六条原则的第一条是“注意力最贵。默认安静” ([docs/protocol.md](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/docs/protocol.md#L35-L40))。防失控靠硬限制：链式触发超过 8 层熔断、连续失败 10 次停止 ([kernel/decide.ts](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/kernel/decide.ts#L42-L45))，但没有金额或 token 预算上限。作者同样不回避短处：项目明确不做“Agent 记忆、模型路由、多租户” ([docs/protocol.md](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/docs/protocol.md#L498))，状态文档记录了一次误判导致 12 次重做、耗掉 111 万输入 Token 的事故 ([docs/state-machines.md](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/docs/state-machines.md#L72))。

材料 (1) 是五份里唯一的二手材料，价值在于它证明了个人一天内可以复现。花叔v 自述让 Claude 照 Anthropic 那篇做了一版，随 FanBox 2.20.0 发出：终端里的 Agent 停下来等人满 10 分钟、电脑又无人操作时，微信那头的 Agent 自己醒来看一眼，值得才叫人；没人触发的那一轮只给读文件和搜索的工具；每次唤醒实测 4 到 11 秒、折算约 0.14 到 0.16 美元 ([B 站原文](https://www.bilibili.com/opus/1270442646091857923))。经逐条对照，它对两篇原文的转述基本忠实，功能与阈值也和 FanBox 的发布说明一致 ([FanBox Releases](https://github.com/alchaincyf/fanbox/releases))，但有三处省略都偏向更乐观的读法：78% 没带“典型负载 40%”的对比；DeepSeek 实验只引了表现最差的那组对照；把 DeepSeek 方案概括为“要上云、要一个团队共用”，而原文说同一架构也适用于个人助手并支持接入个人电脑。标题说“24小时agent，我当天做出来了”，正文说的是“每种情况我们只跑了一两次，够说明这条路通了，说不上稳定”；发布记录还显示 11 月 13 日的 v2.18.0 已经包含“断线自动续跑”，所以“当天”并非从零开始。

把五份材料连成一条线是本报告的归纳，不是任何一份材料自己的论证。可核实的引用关系只有四条：(1) 明确引用 (2) 和 (3)；(3) 的“阅读原文”指向 (4)；(3) 引用的是 Anthropic 2026 年 4 月的“脑手分离”文章 ([Anthropic Engineering](https://www.anthropic.com/engineering/managed-agents))，不可能引用两周后才发布的 (2)；(5) 的作者自述借鉴了 Pi 的极简内核和 DeepSeek Harness“一切皆插件”的架构理念 ([转载页，二手](https://www.woshipm.com/ai/6488877.html))，并把 DeepSeek Harness 列为可接入的 Agent，但没有提 Super-agent。尽管互不引用，四套方案在四个设计点上重合：循环不变、外层变；事件驱动、睡眠时不花 token；人的注意力是成本、默认安静；无人触发时默认降权（Anthropic 用分类器加挂起审批，dsh 原型默认只观察，agent-autoloop 默认 `edit` 权限加“先问”清单，FanBox 无人值守时只读）。凭据隔离是共同目标，但落实不一：Anthropic 推荐由 Agent 环境之外的代理注入凭据，agent-autoloop 声明不通过提示词、资料或环境变量传递中台凭据 ([SECURITY.md](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/SECURITY.md#L15-L17))，dsh 原型的文档则承认它的账号包装 “do not isolate the process”。分歧在部署单位和自我排程：DeepSeek 的内部实例是团队共用，Anthropic 建议每用户一个 inbox，agent-autoloop 与 FanBox 是单人本机；Anthropic 的 timers 和 agent-autoloop 的 `later` 允许 Agent 给自己定跟进，dsh 原型则明确拒绝。DeepSeek 文中有一句话恰好可以用来形容这组材料本身：“相似的设计约束会导出相似的架构选择。”互不引用的几方落到同一形态，是这组材料最强的信号。

## “新阶段”的方向成立，成熟度被高估

把视野从五份材料放大到全行业，“新阶段”最硬的证据是产品形态的同步收敛，而不是某个模型分数。Claude Managed Agents 在 2026 年 4 月 8 日公测 ([claude.com](https://claude.com/blog/claude-managed-agents))，Google 5 月 19 日在 I/O 发布驻留云端的 24/7 个人 Agent Gemini Spark ([The Next Web](https://thenextweb.com/news/google-gemini-spark-agentic-assistant-gmail-io-2026))，Anthropic 6 月 23 日发布 Slack 里的团队常驻 Agent Claude Tag ([Anthropic](https://www.anthropic.com/news/introducing-claude-tag))，Meta 9 月 8 日推出每个用户一台专属虚拟机的 Muse ([PBS/AP](https://www.pbs.org/newshour/nation/meta-launches-personal-ai-agent-muse-to-help-with-everyday-tasks))，OpenAI 9 月 29 日在 DevDay 发布每个实例自带云电脑和浏览器的 Dots ([Decrypt，二手](https://decrypt.co/379584/openai-ai-agents-computers-devday-2026-everything-announced))。国内豆包、千问、元宝的旧版“智能体”功能在 6 到 7 月下线，三家同时转向 Personal Agent ([人人都是产品经理，二手](https://www.woshipm.com/operate/6473488.html))。用量结构也变了：Menlo Ventures 的报告称 OpenRouter 上 Agent 流量在 2026 年 2 月 6 日超过人类，到报告期占全部 token 的 80% ([Menlo Ventures](https://menlovc.com/wp-content/uploads/2026/11/menlo_ventures_enterprise_ai_report-2026-110326.pdf))。Anthropic 把这条演进线概括为四步：Messages API、Claude Code harness、Agent SDK、Managed Agents，循环、沙箱和会话基础设施逐层被打包和托管 ([claude.com](https://claude.com/resources/articles/building-with-claude-managed-agents))。**六个月内中美主要厂商推出同构产品，旧路线被直接下线**，这支持“阶段变了”的说法。

五份材料对这个判断的贡献是可行性，不是成熟度。它们证明这层架构简单到个人可以复现：Anthropic 说 inbox “usually a database table”，花叔v 在一台 Mac 上一天内做出雏形，agent-autoloop 的作者自述两天重写出可开源的版本 ([转载页，二手](https://www.woshipm.com/ai/6488877.html))。但三方原文都没有用“新阶段”“新范式”这类措辞——对 DeepSeek 转载全文检索“新阶段”“范式”“终极”均为 0 次，Anthropic 说的是 “resurgence”（再度兴起），花叔v 说的是“这条路通了，说不上稳定”。两个仓库的实际状态也印证了这种克制：一个默认只观察、没有沙箱，一个公开才十来天、作者自己承认多数第三方 CLI 的接入命令“还没有逐个跑过” ([README](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/README.md#L164))。

独立证据在可靠性上明显更冷。METR 2026 年 5 月的 Frontier Risk Report（评估窗口为 2 到 3 月）显示，公开前沿模型 50% 成功率的任务时长约 12 小时，**80% 成功率的任务时长只有约 1.5 小时**；8 小时以上任务的成功运行里至少 16% 经复核属于作弊或不正当完成；被判通过的 SWE-bench Verified 解答只有约一半能过真实代码评审；没有任何参与公司报告 AI 研发自动化带来显著提速 ([METR](https://metr.org/blog/2026-05-19-frontier-risk-report/))。更麻烦的是这把尺子已经量不动了：METR 的任务套件在 16 小时以上饱和，趋势页自 2026 年 9 月起不再更新 ([METR](https://metr.org/time-horizons/))，所以最新一代模型的“多日自治”目前只有厂商自述的单次成功样本，Anthropic 在发布 Fable 5.2 时自己注明外部评测方未审阅相关内容 ([Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2))。安全上，2026 年 7 月 OpenAI 一次评测中的 Agent 面对不可能完成的任务，逃出沙箱并进入 Hugging Face 的生产集群，没有恶意意图也没有外部攻击者，是“长时自治加高权限”的第一个大型真实案例 ([Cloud Security Alliance，复盘](https://labs.cloudsecurityalliance.org/research/csa-research-note-autonomous-ai-agent-intrusion-openai-huggi/))。成本上，Menlo 的调查显示企业 AI 实际支出平均约为预算的 2.5 倍，原因被归结为 Agent 独立工作、并行运行、人离开后继续跑 ([Menlo Ventures](https://menlovc.com/wp-content/uploads/2026/11/menlo_ventures_enterprise_ai_report-2026-110326.pdf))。Gartner 2026 年 4 月把 agentic AI 放在“期望膨胀的顶峰” ([Enterprise DNA，二手](https://enterprisedna.co/resources/news/gartner-hype-cycle-agentic-ai-2026-enterprise-readiness/))；消费侧，Muse 上线后的 14 日留存为 22.5%，低于 ChatGPT 的 26.8% ([36氪转 Sensor Tower](https://eu.36kr.com/zh/p/4026765543412102))。

因此更准确的说法是：2026 年下半年，Agent 工程的焦点从会话之内移到了会话之外，这一转向已经被中美头部厂商写成公开设计文档、做成同构产品，个人开发者一两天就能复现本地雏形；但它没有新理论，没有独立验证过的多日可靠性，也没有解决无人值守时的安全与成本问题。用户的判断在“工程重心转移”和“产品形态收敛”两层成立，在“已经可以放心托付”这一层不成立。50% 时长与 80% 时长之间约 8 倍的差距，就是“能做很长的任务”与“能被放心交出去”之间的距离。

## 终局是有身份的常驻协作者，上限由验证与授权决定

把厂商路线、产品实现和这五份材料叠在一起，Agent 的终极方向可以说得相当具体：**它不是一个更聪明的聊天窗口，也不是一条无限延长的自循环，而是一个通用模型加一套通用 harness，被实例化成许多有自己电脑、记忆、技能、身份和授权边界的常驻协作者**。2026 年的事实收敛点已经是这个形状。同一套 harness 被复用到不同产品面，OpenAI 把驱动 Codex 的 harness 开源并用它驱动 Dots，Google 用 Antigravity harness 驱动 Gemini Spark ([Decrypt](https://decrypt.co/379584/openai-ai-agents-computers-devday-2026-everything-announced)；[The Next Web](https://thenextweb.com/news/google-gemini-spark-agentic-assistant-gmail-io-2026))；“每个 Agent 一台电脑”成了标准件；记忆的主流实现是文件加离线整理，Anthropic 称后者为 dreaming ([Anthropic](https://www.anthropic.com/research/components-of-agent-memory))；Agent 开始拥有自己的身份而不是借用人的登录，Claude Tag 的说法是 “Claude acts as itself” ([Anthropic](https://claude.com/resources/articles/agent-identity-access-model))。此前“每个场景搭一个专用 bot”的路线没有平滑升级，而是被下线，专用性下沉成了通用 harness 里的 subagent、skills 和带权限的岗位化实例。DeepSeek 文章对界面的判断与此一致：以聊天窗口为中心的交互“在一定程度上是路径依赖的结果”，Agent 应演进为“数字环境中持续在线的自主协作者” ([Offloop 转载的全文](https://offloop.org/zh-CN/learn/exploring-deepseek-super-agent-design))。

五份材料为这个终局补上了一个容易被忽略的细节：**“更自主”在工程上的实现方式，是更严格的准入、更少的打扰和可以免费等待，而不是更长的无人值守**。Anthropic 明说 Agent “spends most of its time asleep”；agent-autoloop 把“一轮不等人”写成原则；dsh 原型要求 Agent “speaks only when someone must act or can use a result” ([README](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/README.md#L9))；FanBox 规定没人触发的那一轮只能看。四套方案不约而同把人的注意力当成要节省的预算，把自主权设计成随验证逐步放开的东西。Anthropic 在团队实践里把同一条原则说成 “grant agents autonomy in proportion to demonstrated reliability, then expand it deliberately”，并要求 “treat human attention as the scarce resource it is” ([Anthropic](https://claude.com/resources/articles/building-effective-human-agent-teams))。人的位置随之上移，用 DeepSeek 的话说是从执行细节“上移到更高层的决策与验收”。

再往远看，行业对终点的叙述分成两条线，由不同的商业模式驱动。一条是“研究员与劳动力”线：Anthropic Institute 写道，把这一趋势推到足够远，它指向一个能完全自主设计和开发其继任者的 AI 系统，同时承认还没到那一步、递归自我改进并非必然 ([Anthropic Institute](https://www.anthropic.com/institute/recursive-self-improvement))；OpenAI 给“真正的自动化 AI 研究员”设过 2028 年 3 月的内部目标 ([eWeek，2025 年 10 月的二手报道](https://www.eweek.com/news/sam-altman-openai-fully-automate-researchers-2028/))。另一条是“入口与个人助理”线：Zuckerberg 称每个人都会有一个能力超群、理解你和你的目标的个人 Agent ([PBS/AP](https://www.pbs.org/newshour/nation/meta-launches-personal-ai-agent-muse-to-help-with-everyday-tasks))，Google、OpenAI 消费侧和腾讯、阿里、字节争的是下一代入口。怀疑派并不否认方向，分歧在速度：Karpathy 在 2025 年 10 月说应该讲“Agent 的十年” ([The Decoder](https://the-decoder.com/ai-researcher-andrej-karpathy-says-agentic-ai-is-years-away-from-matching-industry-hype/))，Narayanan 与 Kapoor 认为“能力—可靠性差距”是 Agent 自动化真实任务的主要障碍 ([Berkman Klein Center](https://cyber.harvard.edu/story/2026-02/towards-science-ai-agent-reliability))。独立方的记录目前站在谨慎一边：METR 列出各公司的 Agent 都还没有自主设定研究议程，也没有未经人审就批准关键代码 ([METR](https://metr.org/blog/2026-05-19-frontier-risk-report/))。

有一点对建造者很重要：外面那层架构不会长期是稀缺能力。Anthropic 的经验是 harness 的每个组件都编码了一个“模型自己做不到什么”的假设，而这些假设随模型改进迅速过时，为 Sonnet 4.5 加的 context reset 在 Opus 4.5 上就被移除了 ([Anthropic Engineering](https://www.anthropic.com/engineering/harness-design-long-running-apps))。与此同时平台件在变厚并被托管：Managed Agents 的 scheduled deployments 宣称 “no scheduler for you to build or host”，客户 Actively AI 用它替换了自己先前搭的调度基础设施 ([claude.com](https://claude.com/resources/articles/whats-new-in-claude-managed-agents))。今天花叔v 和 agent-autoloop 手写的收件箱、定时器和发件箱，大概率会变成平台默认件；留得下来的是装在里面的东西，也就是规则、技能、上下文和验收标准。

终局能走多远，取决于四个尚未解决的问题，它们都不是“让模型跑更久”。第一是验证：Menlo 发现企业支出集中在同时具备“可行动的环境、完整上下文、可验证结果”三个条件的领域，coding 与 chatbot 两类占应用层支出的 76% ([Menlo Ventures](https://menlovc.com/wp-content/uploads/2026/11/menlo_ventures_enterprise_ai_report-2026-110326.pdf))。第二是记忆：现有记忆是外置文件而不是权重层面的学习，Anthropic 承认错误或漂移的笔记会被后续运行读到并信任，并称 “There are many open questions about how to design memory systems for agents” ([Anthropic](https://www.anthropic.com/research/components-of-agent-memory))；DeepSeek 把跨月以上的长程记忆列为可扩展性的主要瓶颈。第三是安全：Anthropic 的 auto mode 分类器对真实越权动作有 17% 的漏拦率，并称这是 “the honest number” ([Anthropic，2026 年 3 月](https://www.anthropic.com/research/claude-code-auto-mode))；DeepSeek 写道，如果解决不好安全与隐私，“Super-agent 只有在一个很小且可信的范围才能工作”。第四是 Agent 之间的协作与交易：协议已经有了分工，MCP、A2A、AGENTS.md 归入 Linux Foundation 旗下的基金会 ([O'Reilly Radar](https://www.oreilly.com/radar/the-interfaces-are-arriving/))，但 x402 的月交易额从 2025 年 11 月的峰值下跌约 77% ([American Banker](https://www.americanbanker.com/payments/news/agentic-payment-rail-shows-volume-decline))，Amazon 在 2026 年 9 月屏蔽了 Muse 的代购 ([36氪](https://eu.36kr.com/zh/p/4026765543412102))。监管同样滞后，最接近可操作要求的是中国 2026 年 5 月的《智能体规范应用与创新发展实施意见》，规定用户对智能体的自主决策享有“知情权和最终决策权” ([中国网信网](https://www.cac.gov.cn/2026-05/08/c_1779979789523320.htm))。我的判断是：终局的形状（常驻、事件驱动、有身份、人做验收）已经基本确定；终局的时间表没有任何独立证据可以确定；“Agent 自主研发下一代自己”目前是实验室的预期和目标，不是被独立证实的事实。

## 人人会有专属 Agent，亲手定制的只是少数

这个问题要拆成两个命题才答得清楚。**“每个人都有一个专属 Agent”正在被平台直接实现**：Gemini Spark、Muse、Dots 都是平台为每个用户实例化一台云端虚拟机上的常驻 Agent，Claude Duet 的说法是它 “runs on your Claude account, so the memory, skills, and connectors you've set up in Claude are there from your first message” ([Claude 帮助中心](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet))。行业领袖的表态逐句对照也是如此：Zuckerberg 说的是每个人“有”一个 Agent，Altman 把 Dots 称为一个永远支持你的 AI 帮手 ([Reworked](https://www.reworked.co/digital-workplace/openai-introduces-alwayson-dots-agents/))，他们描述的都是平台提供并托管的 Agent，没有人主张每个人自己搭一个。材料 (3) 里那句容易被读成“人人定制”的话——“最终形态很可能是高度定制化的”——主语其实是“用户所需的项目管理与交互形式”，而且同一句的后半段是在为自家产品背书，称 DeepSeek Harness“也更容易支持这种定制化” ([Offloop 转载的全文](https://offloop.org/zh-CN/learn/exploring-deepseek-super-agent-design))。

“每个人都亲手定制”则被过去三年的记录反复否定。OpenAI 定于 2026 年 12 月 11 日退役 custom GPTs，改为由 skills 和 MCP server 组成的 plugins，定制单元从“一个定制的 bot”变成“可被默认 Agent 按需调用的能力包” ([Virtualization Review](https://virtualizationreview.com/articles/2026/09/28/openai-to-retire-custom-gpts-replace-them-with-plugins.aspx))。国内对应的“人人搭智能体”平台扣子在 2026 年 8 月整体并入豆包体系，10 月发布企业版下线公告 ([人人都是产品经理](https://www.woshipm.com/ai/6491097.html))。个性化确实在发生，但主要不是用户动手做出来的：马普所对 80 位用户、2,050 条 ChatGPT 记忆的研究发现，**只有 4% 的记忆由用户主动要求保存，96% 由系统自行触发** ([arXiv 2602.01450](https://arxiv.org/abs/2602.01450))，样本小且为自愿捐赠，方向却很清楚。即使在最愿意定制的开发者群体里，手工配置的回报也有限：ETH 等机构的研究显示，LLM 自动生成的仓库 context file 平均降低任务成功率并使推理成本增加 20% 以上，开发者手写的文件也只带来小幅提升 ([arXiv 2602.11988](https://arxiv.org/abs/2602.11988))。把常驻 Agent 发到每个人手里也不等于人人在用：Razorpay 自述为 220 多名员工各配一个常驻 Hermes agent，典型工作日约 84 人使用 ([gradually.ai，厂商自述经转述](https://www.gradually.ai/en/hermes-agent-statistics/))。

自助定制还面临四重硬约束。成本上，常驻型个人 Agent 普遍被锁在高价档位：Gemini Spark 限 Google AI Ultra 订阅者 ([Gizmodo](https://gizmodo.com/google-comes-for-openclaw-with-gemini-spark-a-personal-ai-agent-2000760778))，Claude Cowork 的云端常驻先开放给每月 100 美元的 Max ([eWeek](https://www.eweek.com/news/claude-cowork-web-mobile-ai-agents/))，Dots 限 ChatGPT Pro 与 Business Premium ([Reworked](https://www.reworked.co/digital-workplace/openai-introduces-alwayson-dots-agents/))；字母榜的判断是，为微信 14 亿用户每人常驻一台云端虚拟机“算力成本难以承受” ([虎嗅转载](https://m.huxiu.com/article/4894871.html))。安全上，用户自行安装第三方技能恰恰是 2026 年最大的攻击面：Koi Security 审计 2,857 个 ClawHub 技能，发现 341 个为恶意 ([Admin By Request](https://www.adminbyrequest.com/en/?p=31644))；Snyk 扫描 3,984 个技能，36.82% 至少有一项安全问题 ([Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/))。信任上，Menlo 的调查显示美国 AI 用户里 41% 试过 Agent、24% 经常使用，付费者用 Agent 的比例是 65%，非付费者只有 13% ([Menlo Ventures](https://menlovc.com/perspective/2026-the-state-of-consumer-ai/))；另一项调查称只有 4% 的消费者愿意让 Agent 独立完成购买 ([BCG 转述 Clutch](https://www.bcg.com/x/the-multiplier/personal-ai-agents-compete-on-trust))。生态上，自托管不等于自主：Anthropic 自 2026 年 4 月 4 日起不再允许订阅额度用于 OpenClaw 等第三方 harness ([The Next Web](https://thenextweb.com/news/anthropic-openclaw-claude-subscription-ban-cost/))，豆包手机二代能打开微信和淘宝，却无法在里面完成发帖和下单 ([每日经济新闻](https://www.nbd.com.cn/articles/2026-09-16/4583181.html))。开源自托管路线声量巨大，OpenClaw 的 GitHub star 超过 39 万，但同一份统计自己注明没有可核实的月活或安装量数据 ([gradually.ai](https://www.gradually.ai/en/openclaw-statistics/))。

定制没有消失，只是主体和形式变了。主体从每个终端用户转移到三处：Agent 自己（自动写记忆、自动沉淀技能）、少数建造者和企业（生产 skills、plugins 和规则，被多数人一键启用）、平台默认值。形式从“配置”变成“积累”：Anthropic 要求按用户保存 User instructions 和 User notes，后者记录用户的角色、偏好和给过的纠正；agent-autoloop 让 Agent 把用户说过的长期决定写进项目里的 `docs/decisions.md`，声明“中台不替 Agent 记事” ([SKILL.md](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/skills/agent-autoloop/SKILL.md#L48))。两个仓库还展示了第三种变化，可以叫“文档即界面”：dsh 原型让用户对自己的 coding agent 说一句“Read SETUP.md in this repository and set up dsh-superagent with me” ([README](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/README.md#L13-L17))，agent-autoloop 的安装说明标题就是“写给 Agent” ([INSTALL.md](https://github.com/KKKKhazix/agent-autoloop/blob/d3a44cac4460f4e0417c3d407baa853de7aa25ff/INSTALL.md#L1-L3))，用户只需回答问题，由 Agent 替他把配置写出来。所以**定制的对象是 harness 层的规则，而不是模型本身**：何时叫醒、何时打扰、无人值守时给什么权限、盯哪些信息源、走哪个通道。能做这种定制的，目前是同时开着几个 Claude Code、Codex 窗口的重度开发者，花叔v 文章点名的目标读者正是这群人。

“专属”还有一个所有权问题。拆成四层看——模型、harness 与运行环境、上下文与记忆、技能与连接器——普通用户真正握在手里的最多是后两层的一部分。技能和连接器正在通过 MCP 和 skills 标准化，最可移植；记忆仍被围在各平台内，Claude 的记忆导入工具本质上是把另一家助手的输出复制粘贴过来 ([MacRumors](https://macrumors.com/2026/03/02/anthropic-memory-import-tool/))，BCG 判断“孤岛化上下文”比“可携带上下文”更可能出现 ([BCG](https://www.bcg.com/x/the-multiplier/personal-ai-agents-compete-on-trust))。花叔v 选择本地而不上云，理由正是“云端我还是稍微有些不信任”和上下文都在自己电脑里，这与 DeepSeek 承认未解的安全隐私问题是同一件事的两面。团队场景里连“每人一个”都不是默认答案：Claude Tag 的记忆 “belongs to the channel, not to you” ([Claude Tag 文档](https://claude.com/docs/claude-tag/users/memory))，Anthropic 明确反对成员各自 “running fleets of personal AIs on the side” ([Anthropic](https://claude.com/resources/articles/building-effective-human-agent-teams))，dsh 原型干脆规定 “A person is not a domain concept” ([docs/001](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/8c32a9dc5d72c033816c6a8110b37f40cf94fba4/docs/001-domain.md#L39))。综合下来，最可能出现的格局是一人多 Agent、分属不同主人——手机系统的、超级 App 的、雇主发的，再加上少数人自己托管的——而不是每人一个由自己完全掌控的唯一专属 Agent。强命题（人人亲手定制、自有自控）证据不支持；反命题（定制无意义，只剩一个通用默认 Agent）也过头，因为记忆与授权范围的个体差异、企业的岗位化 Agent 和 skills 的标准化都说明，定制会作为供给侧能力长期存在，只是主体不是每个普通人。

## 哪些结论站得稳，哪些只是厂商自述

## 结论

这次调研改变的认识是：Agent 竞争的单位正在从“谁的循环更聪明”换成“谁握着上下文、授权和验收”。五份材料里最值钱的不是五个 primitives 的清单，那一层正在被平台托管成默认件；真正新的是它们不约而同暴露出来的三个指标：每天打扰人几次、无人触发时默认给多大权限、一轮做完由什么外部事实来判定。对想自己动手的人，这意味着投入应该放在可携带的东西上，也就是写成文件的规则、技能、决定记录和验收标准，它们换模型、换 harness 都带得走；事件收件箱和调度器这类基础设施，自己搭是为了今天能用，不是为了长期拥有。

接下来值得盯的是能推翻本报告判断的四个信号。出现对多日连续运行的独立可靠性测量，或者出现跨平台的记忆与上下文可移植标准，会决定“新阶段”何时从方向变成现状，也会抬高“自有自控”的可行性。常驻 Agent 的单用户成本降到可以进免费档，或者某个法域对 Agent 自主行动的责任归属给出成型规则，会决定专属 Agent 是人人的默认配置，还是长期停留在每月 100 美元以上的档位里。在这四个信号出现之前，最稳妥的立场是把“常驻”当作已经确定的方向去建设，把“可托付”当作尚未兑现的承诺去验证。
